Техническое задание: Модуль интеграции со Steam

1. Введение и общие цели

Настоящее техническое задание описывает требования к разработке модуля интеграции со Steam для нашего приложения. Задача модуля — обеспечить безопасную авторизацию пользователей через Steam OpenID, импортировать библиотеку их игр и реализовать трекинг текущей игровой активности (для проверки гипотезы отображения статуса в реальном времени).

Документ подготовлен для передачи модели Claude Opus в качестве исчерпывающей спецификации разработки.

2. Ключевые задачи из заметок

Подключение игровых аккаунтов: авторизация пользователя через Steam (OpenID).

Импорт библиотеки игр: получение полного списка игр пользователя из его профиля Steam.

Мониторинг активности: отслеживание текущего состояния пользователя (в какой игре он находится в текущий момент) для проверки продуктовой гипотезы.

3. Архитектура и стек технологий

Бэкенд: Python (FastAPI) или Node.js (на выбор разработчика/Claude Opus с учетом текущего стека проекта).

База данных: Реляционная БД (PostgreSQL) с использованием ORM.

Аутентификация: Протокол Steam OpenID 2.0.

Внешний сервис: Steam Web API (необходим параметр конфигурации STEAM_API_KEY).

4. Детальные функциональные требования

4.1. Авторизация через Steam (OpenID 2.0)

Эндпоинт инициализации входа:

При запросе пользователя перенаправлять его на официальный шлюз Steam OpenID: https://steamcommunity.com/openid/login.

Передавать параметры openid.ns, openid.mode = checkid_setup, openid.return_to (URL обратного вызова нашего бэкенда), openid.realm и openid.identity = http://specs.openid.net/auth/2.0/identifier_select.

Эндпоинт обработки ответа (Callback):

Принимать POST/GET запрос от Steam после успешной аутентификации пользователя.

Валидировать подлинность ответа, отправляя запрос обратно на сервера Steam (проверка openid.mode = check_authentication).

Извлекать уникальный 64-битный идентификатор пользователя (SteamID64) из поля openid.claimed_id.

Создавать или обновлять запись пользователя в базе данных нашего сервиса, связывая сессию с его SteamID64.

4.2. Импорт списка игр пользователя (GetOwnedGames)

API метод: IPlayerService/GetOwnedGames/v0001/

Параметры запроса:

key: STEAM_API_KEY

steamid: SteamID64 авторизованного пользователя

include_appinfo: true (для получения названий и иконок)

include_played_free_games: true (опционально, для учета бесплатных игр)

Обработка данных:

Парсить JSON-ответ от Steam API, извлекая массив игр (appid, name, playtime_forever, img_icon_url).

Сохранять или обновлять библиотеку игр пользователя в таблице базы данных с привязкой к его внутреннему ID.

4.3. Отображение активности и проверка гипотезы (GetPlayerSummaries)

API метод: ISteamUser/GetPlayerSummaries/v0002/

Параметры запроса:

key: STEAM_API_KEY

steamids: SteamID64 пользователя (или список через запятую)

Проверяемые параметры в ответе:

personastate: Статус аккаунта (в сети, не в сети, отошел и т.д.).

gameid / gameextrainfo: Наличие этих полей указывает на то, что пользователь в данный момент запустил игру. gameextrainfo содержит текстовое название текущей игры.

Логика работы:

Реализовать механизм опроса (Polling) или фоновой задачи для периодической проверки статуса активных пользователей (либо запуск проверки по запросу клиента).

Передавать актуальный статус активности на клиентскую часть приложения (через REST API или WebSocket) для визуализации статуса «В игре: 

$$Название игры$$

».

5. Требования к безопасности и конфигурации

Секретные данные: STEAM_API_KEY должен храниться исключительно в переменных окружения (.env) и не должен жестко кодироваться в исходном коде.

Безопасность сессий: После успешной валидации OpenID устанавливать защищенный HTTP-only Cookie или выдавать JWT-токен для авторизованных запросов к нашему API.

Обработка ошибок: Предусмотреть обработку недоступности Steam Web API (таймауты, коды ошибок 429 при превышении лимитов запросов, некорректные SteamID).

6. Критерии приемки (Definition of Done)

Пользователь может успешно нажать кнопку «Войти через Steam» и авторизоваться в системе.

После входа система автоматически или по кнопке подтягивает список игр пользователя в базу данных.

В интерфейсе корректно отображается статус пользователя в реальном времени (находится ли он в игре, и в какой именно).
